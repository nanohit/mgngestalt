# Магнитогорское гештальт-сообщество

[Сайт](https://mgngestalt.vercel.app/) · [Кабинет](https://mgngestalt.vercel.app/cabinet)

HTML, CSS и нативные ES-модули. Без фреймворков, сборщика, npm-зависимостей, внешних шрифтов и аналитики. Основной сайт использует оформление бывшей версии `/1`; старые адреса `/1` перенаправляются на основные.

## Размещение

- **Vercel** отдаёт HTML. Серверных функций и секретов приложения на Vercel нет.
- **jsDelivr** отдаёт стили, скрипты, иконки и логотипы из открытого репозитория. При сборке ссылки закрепляются за полным SHA коммита, а относительные импорты модулей остаются на том же CDN. Исходники нужно отправить в GitHub до публикации HTML.
- **Supabase Edge Function `api`** обслуживает вход, кабинеты, пароли и редактирование календаря. Проект: `uwcvheonmfsibqtcfosw` (Ирландия). Постоянного сервера нет.
- **Supabase Postgres** хранит аккаунты, черновики, хеши сессий, счётчики попыток и актуальную копию каталога в `mgg_kv`. SQL-функции доступны только `service_role`; анонимному ключу и `authenticated` доступ закрыт.
- **Публичный Supabase Storage `site`** отдаёт короткий список `data/site.json` (карточки и события без длинных текстов) и отдельные файлы `data/therapists/<id>.json` и `data/events/<id>.json`, которые грузятся только на странице анкеты и при открытии события. Посетители не вызывают функцию кабинета и не читают таблицу аккаунтов. Поиск (по имени, описанию и темам), фильтры и календарь выполняются в браузере.
- **ImgBB** хранит и раздаёт фотографии (`https://i.ibb.co/…`). Функция загружает их через API с ключом `IMGBB_API_KEY`.

Из РФ соединения с Supabase (он за Cloudflare) обрываются после первых ~16 КБ, а Vercel режется так же. Поэтому каждая страница берёт из Supabase как можно меньше: главная — только список (около 1–2 КБ в сжатом виде), анкета — только свой файл. Фото идут с ImgBB, статика — с jsDelivr; они открываются без ограничения. Кабинет тоже не отдаёт полные анкеты списком: полная анкета загружается отдельным запросом при редактировании.

Публикация анкеты или события обновляет JSON в Storage без нового деплоя и без коммита в GitHub. JSON загружается с TTL 10 секунд и минутным `cacheNonce`; после обновления страницы изменения появляются в течение минуты. При недоступности Storage показывается последний снимок, включённый в деплой, с уведомлением. Ветка `content` осталась архивом прежней схемы и больше не используется приложением.

Все четыре существующие анкеты, фотографии и пароли терапевтов перенесены. Администратору выдан новый пароль, сохранённый только локально в игнорируемом файле `artifacts/admin-access.local` с правами 0600. Существующие сессии старого сайта не переносились: участники входят заново.

## Кабинеты

Один администратор создаёт до 40 кабинетов, сбрасывает пароли, редактирует анкеты, календарь и информацию о сообществе. Временные пароли показываются один раз; при первом входе терапевт обязан задать свой пароль. Войти можно по логину, по фамилии или по полному имени из анкеты (регистр и «ё» не важны), если такое совпадение у терапевта единственное. Терапевт редактирует только свою анкету.

В анкете: фотография, описание, образование, стоимость, длительность, формат встреч, необязательные темы и до четырёх контактов. Темы вводятся через запятую (до 12 тем по 40 символов). Фильтр собирается из тем опубликованных анкет. Фото сжимаются в браузере в WebP до 720px и 180 КБ и загружаются на ImgBB; каждая загрузка — новый адрес. Заменённые фото остаются на ImgBB по своей ссылке (API не удаляет), удалить их можно вручную в аккаунте ImgBB. Если фото не загрузилось за 10 секунд, вместо него показываются инициалы.

Даты событий показываются по времени Магнитогорска — `Asia/Yekaterinburg`, UTC+5. Посетители записываются напрямую через указанные специалистом контакты. Сайт не хранит обращения пациентов, записи на приём и платежи.

`?demo=1` — отдельный режим примеров с заметным баннером. Обычный каталог использует только записи администратора и терапевтов.

## Секреты и защита

Edge Function использует встроенные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Дополнительный секрет `ADMIN_PASSWORD_HASH` нужен для первого администратора и проверки несуществующих логинов, `IMGBB_API_KEY` — для загрузки фото. Пароли хешируются `scrypt` с индивидуальной солью. Серверный ключ и токен управления Supabase не попадают в `public/`, Git или браузер.

В `supabase/config.toml` задано `verify_jwt = false`: приложение использует собственную авторизацию кабинета, а не Supabase Auth. Клиент передаёт случайный токен в `Authorization: Bearer`; в базе лежит только его SHA-256. Токен хранится в `sessionStorage` текущей вкладки, срок на сервере — 7 суток. Выход, смена и сброс пароля отменяют старые сессии. CORS разрешает обращения с другого домена без cookies; все операции изменения требуют валидной сессии и JSON.

Сервер проверяет роли, принадлежность анкеты, входные данные и ревизии. Ограничены попытки входа, действия аккаунтов, размер запросов, число кабинетов и событий. Общая короткая блокировка предотвращает одновременные записи. При сбое публичного хранилища анкета остаётся в черновике и кабинет сообщает об ошибке публикации; версия календаря не меняется при неудачной загрузке JSON.

HTML экранируется; контакты допускают HTTP(S), `tel` и `mailto`. CSP разрешает только источники статики и Supabase, запрещает inline-скрипты и встраивание сайта. Публичные файлы доступны всем; база аккаунтов закрыта RLS и ограничением прав на RPC.

## Разработка и публикация

```sh
npm run dev       # http://127.0.0.1:4173
npm run check     # синтаксис JS и JSON
npm test          # сценарии API с изолированными HTTP-адаптерами
npm run build     # dist/ с CDN-ссылками за текущим коммитом

deno check --node-modules-dir=none supabase/functions/api/index.ts
supabase functions deploy api --use-api --project-ref uwcvheonmfsibqtcfosw
```

CLI Supabase получает `SUPABASE_ACCESS_TOKEN` из окружения терминала. Не передавайте секреты аргументами команд и не сохраняйте их в отслеживаемых файлах. Изменения `lib/` требуют отдельного деплоя функции; Git integration Vercel публикует только статику.

Перед развёртыванием в новом проекте примените `supabase/schema.sql` через SQL Editor и измените публичные адреса в `public/config.js`, CSP и `supabase/config.toml`. `node scripts/setup-admin.mjs` создаёт первоначальный пароль, только если администратора ещё нет, и устанавливает его хеш через Management API. Для локального API можно использовать `.env.local` по образцу `.env.example`; настоящие Production-ключи изменяют настоящий каталог. По умолчанию локальный кабинет обращается к опубликованной функции Supabase.

Vercel сборка не требует секретов приложения. Для проверки неопубликованных изменений используйте локальный сервер: CDN получает файлы только после push. В production сначала отправьте коммит в GitHub, затем публикуйте HTML. Встроенные Node-инструменты не собирают бандлы и не меняют исходники.

## Сопровождение

Схема рассчитана на небольшой каталог и редкие действия участников. Платные опции, upgrade и внешние фоновые процессы не нужны для этой реализации; расходуются лимиты Supabase на Postgres, Storage, трафик и вызовы функции. Следите за ними в панели Supabase и сверяйте [лимиты Free](https://supabase.com/pricing). Бесплатный проект может [приостанавливаться при низкой активности](https://supabase.com/docs/guides/platform/free-project-pausing) — для восстановления понадобится панель проекта.

Резервируйте закрытую таблицу аккаунтов и Storage отдельно от открытого репозитория. История Git содержит код и архив прежних публичных данных, но не новые черновики и пароли. При восстановлении каталога приведите в соответствие запись `site` в Postgres и публичный `data/site.json`. Старые версии фотографий можно удалить из Storage после проверки, что ни одна анкета или черновик их не использует.
